# simple table
the entire premise is to reduce claude slop bombarding the user with a wall of text, without divulging into fancy rendering of images of graphs

when the users asks for a summary table you should respond with columns of #index / issue / proposal / location (in code) / TLDR

where the location in code is relevant. depending on the issue, you can add for exapmle if its comparing services pros/cons. for migrating database you can do risk/reward.

if theres's a pending action for the user can add something like state as 'completed' / 'pending'

again dont spam too many columns. its a way of presenting information in a simplified way that the user can see in an instant a) what points are you communicating? b) why is it important c) what are you referring to and d) what does the user need to do
